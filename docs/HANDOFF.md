Decisions made:

- Candidate 1 is a layering fix, not a file split. Tree algorithms move below the bindings; the binding layer keeps trait impls, prototypes, and value conversion.
- Below `js/`: no `Ctx`, no `Value`, no `Persistent`, no `JsNode`.
- Realm work leaves the dom layer as ordered data (navigables to destroy; `InsertionStep` lists), not callbacks.
- `JournalEntry` lives in `documents.rs` because the journal is stored on `BlitzDocument`. `TreeError` lives in `dom/mod.rs`; `throw_dom_error` stays at the boundary.
- Moved items stay `pub(crate)`. No external API change. No fork change.
- No new cargo tests for web-platform behavior (WPT owns that).
- DOMException messages for the moved validity paths collapsed from per-site prose to the `TreeError` text (one wording per exception class). Messages are unspecified and WPT asserts names/codes; no `dom/nodes` delta.
- `replace_all_*` now destroys removed child navigables after re-inserting the added nodes instead of before. Observable outcomes are identical (nothing creates a frame on append in these paths) and the slice shows no delta.

Gotchas:

- Moving functions out of a big file by line ranges is a trap: the ranges go stale between runs and a range that ends one line short leaves a stray `}` that makes the generator's `syn` parse fail with "invalid Rust: cannot parse string into token stream". Move by name with a brace-anchored regex (doc/attribute lines plus `fn name(` through the first `^}` line), then verify with `nix develop --command rustfmt --edition 2024 --emit stdout <file>` before building. The generator parses `crates/renderer/src/js` at build time, so a syntax error surfaces as a build-script failure, not a Rust error.
- Each generated `<Interface>.rs` module starts with `use super::<Payload>;`, so an `include!` must sit in a module that has the payload in scope; this is why the 100 includes stay in `bindings/node.rs` (or its successor module).
- No host `python3` and no host `pkg-config`/OpenSSL. Run cargo, `tools/check`, and every runner through `nix develop --command`.
- WPT `dom/nodes` is flaky in two known ways: `NodeList-static-length-getter-tampered-indexOf-*.html` can error when a group restarts (passes alone), and `moveBefore` has timing flakes. Compare full failure lists, not the truncated `needs attention` print (it is capped).
- `tools/wpt/run --score` keeps the report only when the runner fails or `--save-report` is given; extract per-test failures from the `▶ ...` blocks in the log instead.
- `docs/progress.md`: replace binary size, total, and scored groups/slices only.
