# Upstream bugs

Policy: upstream bugs stay upstream. Our code stays simple; these fail closed as known-fails. On fork syncs, upstream wins conflicts: take upstream's shape and re-apply the fork patch on top of it, even where the fork had fixed the code the change rewrites — the fork carries fixes upstream has not taken yet, not a competing design.

## Fork changes

### blitz (third_party/blitz, master)

- 68aee6569 image requests own their identity, and each node reports one settlement. Image request identity was split between Blitz and the embedder: Blitz keyed its image cache and pending map by URL, so two `<img>` on one URL with different `crossorigin` shared one request, a cache hit settled nothing, and the embedder recomputed the key by re-parsing the attribute and re-resolving the URL. `ImageKey` (URL plus parsed `CorsSetting`) is now the key, `Request` carries the initiating `node`, the parsed CORS state, and the sampled `referrerpolicy`, `BaseDocument::image_requests` compares request state so a same-state write does nothing, and `DocumentConfig::image_settle` reports `Started`/`Loaded`/`Failed` per node (`https://html.spec.whatwg.org/multipage/images.html#reacting-to-dom-mutations`, `https://html.spec.whatwg.org/multipage/links.html#link-type-stylesheet`). Upstream Blitz has the same URL-keyed cache and no settle event; this is a generic fix, not tinybrowser glue, and should be proposed upstream once the shape has settled (no upstream PR is open yet). `srcset` and `<picture>` `<source>` selection is still unimplemented: a broken request is reported for those elements so they do not wait for pixels that never arrive.
- f7519a948 keep one checkedness slot, reload the sheet a changed instruction names, and parse pseudo-attributes strictly. `FormControlState` has private fields and one `Dirtiness::apply`; creation, reset, and clone share one seed and one `:checked` derivation, a type change re-derives `:checked`, and `SpecialElementData::CheckboxInput` no longer carries a second checkedness copy that box construction overwrote from the `checked` attribute. A user interaction sets the dirty checkedness flag, so a later attribute write cannot undo it. A connected `xml-stylesheet` instruction reloads its sheet on a data or attribute write (`https://www.w3.org/TR/xml-stylesheet/`), the loader parses the data itself, as `CheckStyleSheet` does, so an attribute map holding a DOM-only name cannot make a parse error load, and a response for the sheet the instruction named before cannot install over the new one. Character references accept any number of leading zeros and only the lowercase `x` form.
- 9470daff5 keep a checkedness slot in every input state and gate `:checked` by the widget state. The slot was seeded and reset only for checkbox and radio inputs, so a text input's `.checked` changed after an attribute write or a reset. `store_checkedness` also mirrored `:checked` unconditionally, and the type keyword was matched case-sensitively. Typed writers take a `Dirtiness` (keep/set/clear) instead of a bool whose meaning differed per setter; the select reset clears the option dirtiness through the same write. The pseudo-attribute parser no longer rejects a character reference with long leading zeros, no longer accepts the uppercase `&#X` form XML does not define, and no longer re-validates a name it has already scanned.
- 428bd1bc1 resolve `xml5ever` to the sibling html5ever fork in `Cargo.lock`. A `[patch.crates-io]` entry does not replace a locked registry version on its own, so the workspace kept building `blitz-dom` against crates.io `xml5ever`, which has no `names` module.
- 5dfb348b5 carry a processing instruction's attribute map on its node. The strict parser is the only source for the attributes, so deriving them from the data on every read lost names the DOM attribute API accepts but the XML `Name` production rejects (an attribute local name such as `$`). Creation and every data write derive the list; an attribute mutation serializes the list into the data and stores it in one step, and the accessors read that list.
- 5ab7b943c form-control slots are the current state and the flags are the spec's dirty flags. `FormControlState` used to mean "the slot is live, otherwise read the attribute", so every writer dirtied the slot and the `Option()` constructor, the selectedness setting algorithm, and form reset could not write a slot without hiding a later attribute change; an embedder had to rebuild selectedness, dirtiness, and a pristine-value marker beside it. Now the slots are authoritative and the flags only record the spec's dirtying steps. Elements seed the slots from their initial attributes because parsers create elements with the attribute list instead of calling `set_attribute`.
- b50a4b405 parse `xml-stylesheet` pseudo-attributes with the XML grammar. The style-sheet loader scanned the data leniently while embedders parsed it strictly, so `<?xml-stylesheet href="a&b.css"?>` fetched a sheet the DOM exposed no attributes for. One strict parser answers both and a parse error loads nothing (`https://www.w3.org/TR/xml-stylesheet/#dt-parsing`). blitz-dom depends on the html5ever fork's `xml5ever::names`, which its workspace patches to the sibling submodule.
- cefc1bb08 fetch the images CSS references and send their sheet's referrer. `content: url()` and the legacy `background` content attribute make the browser load an image even when nothing paints it (`https://drafts.csswg.org/css-content/#content-property`, `https://html.spec.whatwg.org/multipage/rendering.html#the-background-attribute`). A sheet's image URLs are recorded against its location when it loads, so the request sends the sheet's URL as its referrer and applies the sheet response's `Referrer-Policy` (`https://w3c.github.io/webappsec-referrer-policy/#integration-with-css`); the document base URL moves onto the node tree so the `background` hint can resolve it. A `<style>` outside the document no longer attaches a sheet, which also removed a second parse of the same element that raced two `@import` fetches.
- e92ec16af respond to an image request under the URL it was made with, not the response URL. `pending_images` is keyed by the request URL, so a redirected delivery never matched and the image stayed pending forever. Stylesheets keep the resolved URL, which is the response URL their origin-clean check needs.
- da340bdd0 load style sheets from `xml-stylesheet` processing instructions. A `<?xml-stylesheet?>` instruction names a sheet exactly as `<link rel=stylesheet>` does, and an HTML tree keeps the instruction for compatibility with XML-authored sheets (`https://www.w3.org/TR/xml-stylesheet/`), so it has to load. The instruction owns its sheet without element storage, so the owner map records it and the unload path updates the stylist directly.
- 46d832aab give a style sheet's requests the sheet's referrer and policy. A resource a sheet references sends the sheet's URL as its referrer and applies the sheet response's `Referrer-Policy`, not the document's (`https://w3c.github.io/webappsec-referrer-policy/#integration-with-css`). `Request` carries the sheet URL, and the loaders thread each sheet's location through parsing, `@import` nesting, and `@font-face` fetches.

The BMP decode feature is not a fork change: which formats an engine carries is the embedder's compile-time choice, enabled through `crates/renderer`'s `image` dependency and unified here (commit 095af30a2 reverts the fork's own toggle).

- c62d5c63 resolve_url returns None instead of panicking. A relative ref against a non-base (observed: foo.jpg against data:text/css) panicked the engine; unresolvable URLs now skip the fetch and form submission returns early.
- 7189584d real doctype, processing-instruction, and CDATA nodes. These are real DOM nodes; a tree that cannot represent them forces every embedder to rebuild them from source with side tables.
- 4954fea7 keep PI data, doctype nodes; drop only the XML declaration. The declaration is prolog, not content, so it creates no node; a later reserved-target PI stays a real node.
- ffec5987 template contents fragments and Fragment nodes. ElementData already carried a template_contents slot nothing filled, and deep clone shared the original; now templates are born with contents and clone/move preserve them.
- 96443edf host-linked fragments; template fragment parsing lands in contents. Cycle checks must see through fragments, and html5ever never opens the context element so its template modes have nowhere to route into.
- 5f6172ed carry sink parse errors on the document for draining. HTML ignores them (error-tolerant) while XML consumers decide parsererror documents from them.
- a6906d6b fail closed on deep entity nesting, scan only the prolog for DOCTYPE, record one error. Deep nesting used to stop silently and leave a well-formed document (billion-laughs hole); a doctype keyword inside comments/PIs declared entities; 10k bad references produced 10k strings.
- c3581533 let xml5ever expand internal general entities. The 797-line bounds module belongs to the parser crate that owns the DTD subset.
- 791d7655 drop the on-demand style context inside the layout state. SequentialTaskList::drop asserts the state, so getComputedStyle on display:none panicked as soon as the context dropped.
- 9f10f12e display:contents generates no box for resolved values. Per CSSOM, no box means the resolved value is the computed value; it reported 0px and leaked min/max clamping in.
- 19672f4f tag requests with their resource kind (stylesheets, images, fonts). Per-destination policy (CSP `img-src` / `style-src` / `font-src`) cannot be applied from the URL alone; the embedder would have to guess the destination.
- 75a78a6c7 read-only stylo device accessor. Value sanitization reads the color scheme while holding only a shared document reference, and the flushing accessor needs `&mut self`.
- 4736fc73 accept a leading `+` in canvas width/height attributes. The HTML non-negative integer parser allows it, so `width="+100"` is 100.
- 83251583 parse canvas width/height attributes as non-negative integers. `100%`, `100e1`, and `0x100` are 100, 100, and 0, not a CSS length and a parse failure; the intrinsic size and the computed width both depend on it.
- 82eb84a8 expose the document font context. Canvas text must shape with the database holding `@font-face` fonts; the shared process context does not see them, so an embedder cannot otherwise measure or draw the fonts a page declares.
- c198da78 accept zero-sized SVG images. usvg rejects width or height 0, so a valid image with no painted area was reported as a failed load; the declared intrinsic size now survives and `naturalWidth` / `naturalHeight` can be 0 without an error.
- ab3cb6c3 load `<img src>` while detached. `new Image()` never enters a document, but the spec starts the image request when `src` is set; the special-attribute path returned early for detached nodes, so script-created images never fetched and canvas `drawImage` waited forever for `load`.
- 6f761083 match `:focus-visible` from the `FOCUSRING` element state and keep the fork's real `:focus-within`. Stylo's `:focus-visible` branch was hardcoded false, so keyboard focus never matched the pseudo-class; `focus()` now receives the caller's focus-visible decision and the UA sheet uses `:focus-visible`.

### html5ever (third_party/html5ever, master)

- 9043b4f test every boundary of the `names` ranges and document all five productions. The earlier tests sampled a few points of the tables they sit next to, so a typo in an unsampled range stayed green.
- e2f6bcd one public `names` module for the XML `Name`, `Char`, and `S` productions. xml5ever's entity expander and tinybrowser carried byte-identical range tables, and tinybrowser carried a third copy for `createProcessingInstruction` and the pseudo-attribute parser. The module is self-contained, but upstream's tokenizer still matches `S` with literal `'\t' | '\n' | ' '` sets, so it would land without a consumer; it stays fork-only until upstream grows one, and the tokenizer keeps upstream's literals rather than rewriting twelve match arms into guards for no behavior change.
- 1753ef5 keep xmlns attributes, CDATA nodes, strict EOF/doctype. DOM trees need what out-of-band-namespace embedders do not; restores the essence of upstream #586 (reverted upstream in #595). EOF-with-open-elements and PUBLIC-without-SYSTEM are well-formedness violations that must surface as parsererror.
- b71b746 skip the internal DTD subset instead of going bogus. The subset carries no tree data (expansion runs up front) but its presence must not poison the doctype token.
- 39ba978 / bac928b prolog-only documents, then EOF-before-root is an error. First half accepted rootless input, then the start-phase half was reverted: the XML document production requires exactly one root, as Gecko and Chromium enforce. Unclosed roots are still caught in the end phase.
- 37c1cb0 expand internal general entities in the parser. Moved from blitz-html source pre-expansion; the driver owns it so markup inside replacement text parses and errors reach the sink.
- ae2057f fail closed on budget exhaustion and keep literals intact. Oversized replacements were half-copied, and expanded text containing the attribute delimiter could re-delimit the value or start a new reference.
- 08c7e33 drop the unused TreeSink import. Warning cleanup.

### rquickjs (third_party/rquickjs, master)

Exotic hooks for WebIDL legacy platform objects (dcd8edd, 9bcc543, 42688aa, 31e1683, 62d9c1a, 09be401, f99e205, 52744cf, cfc6c77, de4b9d9). The shared QuickJS class installed get/has/set callbacks for every exotic object, hiding prototypes and swallowing ordinary assignment. Now each Rust type registers only its derived hooks with explicit fallthrough to the ordinary path, so OwnPropertyKeys ordering, IsDataDescriptor, and receiver/holder distinction match WebIDL. Each engine-side fix has a binding proof that was red before it.

- d73fbda safe realm-aware native callbacks with copyable dispatch state. Callbacks keep argument counts, receive new.target, and run in their creation realm; Copy/Send/Sync-only state fits GC (no Rust destructors mid-collection).
- 8842327 UTF-16 string conversion preserving lone surrogates. WebIDL DOMString conversion keeps every code unit; pairs with the blitz UTF-8 open issue below (JS side preserves, DOM side does not).
- 103de1e survive caught panics and regenerated binding types. A panic caught across FFI poisoned the mutex and broke every later call; plus an MSVC atom-type build fix and per-target test gating.
  - tinybrowser's release profile cannot honor this: `panic = "abort"` means std's `catch_unwind` never catches, so a Rust panic in a native callback aborts the renderer instead of raising a JS exception. Catching requires unwinding, measured at 13.59 MiB vs 10.61 MiB shipped (+2.98 MiB, `docs/size.md`), so it stays rejected; the panic hook records the panic with location (`crates/logging/src/crash.rs`) and callback paths must stay panic-free. The guard remains correct for unwind hosts (tests, embedders).
  - Deferred direction: redesign the fork so it never catches a panic to begin with (no `catch_unwind`, callbacks assumed panic-free), which makes the abort profile the documented contract instead of an exception to the guard.
- ad2fb33 expose the string compilation host hook. `Runtime::set_can_compile_strings` binds `JS_SetCanCompileStringsHandler` with the callback's `Ctx` and source, mirroring the interrupt and rejection handlers; bundle the new symbol for every target.
- ba4e459 safe `TypedArray::to_vec`. Embedders needed a copy that survives JavaScript execution, detach, and resize; the only alternatives were `as_slice` under `unsafe` or an `Array.from` round trip per element. Form bodies, page/XHR request bodies, the XML response decoder, and TextDecoder input now cross as `Uint8Array`.
- Tracking (11c770e, 7ca6024, 38c4d87, a86ed40, 3587d7e, 50b403e, c161d25): pull quickjs engine fixes and regenerate bindings; wasm OOM/atom-table/inline mirrors.

## Open issues

- Character data, titles, and attributes keep lone surrogates in a tinybrowser side table (`exact_text`, `exact_attrs`). The layout tree still stores lossy UTF-8, so style matching never sees a U+FFFD stand-in. Fixed on our side, not in the fork's storage.
- `blitz-dom` hosts shadow roots (`NodeData::ShadowRoot`, `ElementData::shadow_root`, blitz@ca29873). `attachShadow` returns the root, closed mode makes `shadowRoot` null, and style walks the shadow host without panicking. `ShadowRootInit` members other than `mode` (`delegatesFocus`, `clonable`, `serializable`, `slotAssignment`) are not stored. Shadow-scoped cascade data is still absent, so a `<style>` inside a shadow tree does not apply, and box construction still walks light-DOM children. Composed events do not cross a shadow root: the path stops there and `event.target` is not retargeted to the host. `getComposedRanges` stays a no-op. Partially fixed in fork.
- Reading `HTMLTemplateElement.content` copies the template contents into an inert document. `content.ownerDocument` is that document. Nested templates that have not been read stay same-document fragments inside it. Fixed on our side (fragment plumbing remains blitz@ffec5987/96443edf).
- XML namespace prefix synthesis on serialization is skipped (stored qualified names used as-is). Open, not fixed in fork. Entity half is fixed: internal general entities covered by blitz@c3581533 and html5ever@37c1cb0/ae2057f.
- `ElementData.form_state` stores the value, checkedness, selectedness, and indeterminate slots with the spec's dirty flags (blitz@5ab7b943c/9470daff5/f7519a948). The slots are authoritative: a content attribute updates one only while its flag is clear, the IDL setters and user interaction set the flag, and the type-change and reset algorithms clear it. `:checked` follows the checkedness slot in the Checkbox and Radio Button states and the selectedness slot on options; `:indeterminate` reads its flag. Fixed in fork. Value sanitization still runs in the renderer (`dom/input.rs`) because the input type states and their microsyntax tables do, so a parser path that creates a control calls back into the renderer; one state boundary remains. `select` events still have no producer.
- `blitz-dom` exposes no image-request state: `image_cache` / `pending_images` are `pub(crate)`, so request tracking (selected `currentSrc`, loading/broken flags, `load` / `error` events) stays ours; the decoded result itself is public (`ElementData::image_data`), so `naturalWidth` / `naturalHeight` and the `load` / `error` decision read Blitz state with no second decode. SVG and GIF `<img>` now load like Chromium. Open upstream gap, handled on our side.
- SVG `<image>` elements do not carry decoded image data after Blitz resolves their `href`; only HTML `<img>` gets `ElementData::image_data`. `createPattern` therefore cannot distinguish a missing resource from a valid zero-sized one for `<svg><image>`, and returns null for both, failing `2d.pattern.svgimage.nonexistent`. Open, not worked around.
- Canvas gradient interpolation: the HTML Standard says stops are converted to the context color space and linearly interpolated there, which is sRGB for the default context. `2d.gradient.colormix` and `2d.gradient.relativecolor` expect Oklab values, and the `CanvasGradient.colorInterpolationMethod` attribute their sibling reftest uses is absent from the HTML source. tinybrowser follows the spec (sRGB) because the older `2d.gradient.interpolate.*` values and reference images also assume sRGB. Open spec/WPT gap; revisit when `colorInterpolationMethod` ships.
- `DocumentConfig.quirks_mode` locks the stylist to the doctype sniff before parse (blitz@48a1590f), so html5ever's empty system id cannot override it. `document.compatMode` and layout share that mode. Fixed in fork. User-agent sheets stay NoQuirks.
- `blitz-html` sniffs XHTML by substring (`html_sink.rs:parse_into_mutator`: first line containing `XHTML`/`xhtml`, or an `xmlns` on the root) and parses the whole document as XML. Any `text/html` document whose first line mentions XHTML — e.g. an XHTML-transitional doctype — loses every node after the first well-formedness error. The HTML parser must never go XML from the doctype. Open, not fixed in fork, not worked around.
- `blitz-dom` puts `AnonymousBlock` layout boxes in the same tree. Open upstream gap, handled on our side as transparent (snapshot/serialize children only, never brand as elements).
- `blitz-dom` exposes only the viewport scroll offset, no per-element scroll-container offset API. Open, not fixed in fork.
- `blitz-dom` owns document language internally with no metadata setter, so a response `Content-Language` is not applied. Open, not fixed in fork.
- Document and fragment parses set `scripting_enabled` (blitz@48a1590f), so `noscript` is raw text. Fixed in fork.
- `blitz-dom` matches `:placeholder-shown` from `ElementState::PLACEHOLDER_SHOWN` (blitz@bcf0197). The bit follows the live control value: `editor.raw_text()` once a text editor exists, otherwise the value attribute or textarea text. An input event snapshots the bit, so typing clears it without writing the value attribute. Fixed in fork.
- `blitz-dom` inserts a document stylesheet before the tree-order successor of its owner, and `document.styleSheets` walks those owners in the same tree order (blitz@bcf0197), so moving the owner changes both cascade position and CSSOM order. Fixed in fork.
- `moveBefore` reparents through `DocumentMutator::move_node` (blitz@ca29873), which skips the insertion and removing steps and re-seats stylesheets already in the cascade. Fixed in fork.
- `tiny-skia` under-covers pixels on a canvas border when a path extends past the bitmap edge: an arc whose boundary lies just outside pixel (0,0) gets 239/255 coverage there, while the same path shifted one pixel inward gets 255. `2d.path.arc.scale.1` asserts those corner pixels, so the shape is right but the edge pixel is not. Open, not worked around.
- `hyper`'s HTTP/1 parser (`httparse`) rejects response header values containing control bytes other than TAB (0x0B, 0x0C, 0x7F, …), so the whole response fails before tinybrowser sees it. Chrome and Firefox accept such values; WPT relies on it (`mimesniff/mime-types/charset-parameter.window.js` heads six navigable fixtures with these bytes). Open, not worked around.
- `hyper` / `http::HeaderName` lowercases request header names when parsing and serializing. WPT `fetch/api/basic/request-headers-case.any.js` expects the page's original casing on the wire. Open, not worked around.
- The remaining `__tbToLatin1` conversions produce the spec-visible isomorphic string for `btoa` (`__tbBase64Encode`) and `FileReader`; they are not a missing typed-array API.
- `rquickjs` native functions receive every parameter by value (`Ctx`, `Value`, `String`). The binding layer never consumes most of them, so `clippy::needless_pass_by_value` fires across the whole module tree; one module-wide expectation in `crates/renderer/src/js/mod.rs` states that fact once. A fork ABI taking `&Ctx<'js>` and `&Value<'js>` removes the expectation. Open, tracked as an rquickjs fork gap.
- `Response` body-mixin methods create `Uint8Array`/`ArrayBuffer` objects in the shim realm, not the receiver's realm. `response-blob-realm.any.html` and `response-arraybuffer-realm.window.html` inspect the constructor realm and stay red. Creating a typed array in an arbitrary QuickJS realm has no safe binding yet. Open.
- Service workers are not implemented, so every `serviceWorker.getRegistration`/`register` WPT path fails (`fetch/api/request/destination/*`, `fetch/api/policies/*-service-worker.https.html`, `fetch/api/abort/serviceworker-intercepted.https.html`). Open feature gap, not a workaround target.
- `Request.destination` is `""` for page `fetch`, but `Sec-Fetch-Dest` for element subresources is only as fine-grained as the renderer's dial kind. Blitz gives images, styles, scripts, and frames distinct kinds; preload/font/manifest paths remain coarse. Open feature gap.
- `mimesniff/mime-types/parsing.any.js` drives the MIME parser through `Blob`/`File` `type`, but FileAPI defines that type as the raw string ASCII-lowercased (rejected only when a code unit falls outside U+0020..U+007E), so the two cannot both hold for inputs like `TEXT/HTML;CHARSET=GBK`. Both browsers implement FileAPI and fail the file (712/1898 Chrome, 1031/1898 Firefox at WPT 9f868fd7, while `FileAPI/blob/Blob-constructor.any.html` is 73/73 in both). The `Request`/`Response` `blob()` half does extract a MIME type and passes. Open, not worked around.
- Blitz hardcodes `:valid` and `:invalid` to false (`packages/blitz-dom/src/stylo.rs`, `match_non_ts_pseudo_class`). tinybrowser's `ValidityState`, `checkValidity`, and `willValidate` are implemented in JS, but selector matching never sees that state. `pattern_attribute.html`, `infinite_backtracking.tentative.html`, `input-number-validity-dynamic-value-no-change.html`, and one `placeholder-label-option-wrapper.html` subtest fail only on `matches(":valid"/":invalid")`. Open, not worked around.
- Blitz's `:disabled` / `:enabled` state covers only a control's own `disabled` attribute and only the local names in `ElementData::can_be_disabled` (button, input, select, textarea). It has no disabled-`fieldset` inheritance, no first-`legend` exception, and no disabled `fieldset`/`optgroup`/`option` state. tinybrowser's focus and validation paths implement `is_actually_disabled` correctly, but CSS matching cannot use it. `disabled-nested-legend.html`, `disabled-003.html`, and `option-disabled-optgroup.html` stay red. Open, not worked around.
- The WebIDL binding layer does not install named/indexed own-property hooks for `HTMLFormElement` or indexed hooks for `HTMLSelectElement`; it generates only the named operations. `form.foo`, `form[0]`, `select[i]`, and `select.options.add(index)` therefore lack the legacy platform object behavior even though the rquickjs fork's exotic hooks support it. This accounts for `form-nameditem.html` (11), `implicit-submission.optional.html` (3), `form-indexed-element.html` (2), and the `HTMLOptionsCollection` index tests. Open, not worked around.
- Customizable select and filterable select need layout and CSS features Blitz/stylo do not have: `appearance: base-select`, `::picker(select)`, `::picker-icon`, `::checkmark`, top-layer/popover geometry and exit animation, `selectedcontent` insertion/removal steps, and `:filtered`. About 250 WPT subtests remain in that family. Open, not worked around.
- Blitz's `Document::active_node()` applies `:active` to the hit node and its ancestors but does not forward it to a label's labeled control. Our input path can set the control's state for synthetic actions, but real pointer dispatch bypasses it. Four `checkable-active-onblur-with-click.html` label cases stay red. Open, not worked around.
- Form association does not cross shadow roots: the `form` attribute lookup walks the light tree, and `form.elements` does not filter to the same shadow tree. `form-attribute-form-owner.html` (shadow case) and `form-elements-filter.html` (shadow cases) stay red. Open, not worked around.
- Controls inside a misnested `<table><form>` associate through the HTML parser's form element pointer, not an ancestor. `form_owner_of` only checks the `form` attribute and ancestors, so two `form-control-infrastructure/form.html` label cases report a null form owner. Open, not worked around.
- `window.getSelection()` is not implemented, so `email-set-value.html` and `selection-pointer.html` fail before they reach form behavior. Open, not worked around.
- A form action URL's non-ASCII query is serialized as UTF-8 even when the document encoding is windows-1252; `action-encoding.html` expects `%DF`. Open, not worked around.

- Proposal tests fail everywhere by design: HTML `<?...?>` stays a bogus comment per the HTML Standard (the PI-attributes proposal expects PI nodes), and two PI value subtests (`axx>`, `some<>`) contradict the spec's own escaping algorithm. By design, not a bug.
- `fetch/api/response/response-consume-empty.any.js` expects an empty body for a `FormData` with no entries. The multipart/form-data serializer still emits the closing `--boundary--\r\n`, as `fetch/api/response/response-form-data.html` requires, and Chrome's shipped behavior matches the serializer. tinybrowser follows the serializer algorithm, so the response file stays red until WPT or the spec changes. A `Request` with empty `FormData` already serializes zero bytes for `fetch/api/request/request-consume-empty.any.js`.
- `blitz-dom` names the fragment node kind per site: `NodeData::Fragment` and `NodeData::ShadowRoot` are two variants, so every embedder that asks "is this a document fragment" writes `Fragment | ShadowRoot` again (`crates/renderer/src/documents.rs`, `js/bindings/node/core.rs`, `js/bindings/node/element.rs`). A `NodeData::is_document_fragment()` predicate next to the variants (blitz@ffec5987) would give every embedder the same answer. Open, handled on our side.
- `blitz-traits`' `RequestKind` has an `Other` variant with no destination, so an embedder that gates requests by destination has to guess what the request is. Today the only unclassified resource a document hands Blitz is an image a style sheet named, and tinybrowser treats `Other` as an image in one exhaustive match (`crates/renderer/src/document/mod.rs`). Blitz classifying what it fetches would delete the guess. Open, handled on our side.
- Fetch's main fetch makes a `no-cors` request whose redirect mode is not `"follow"` a network error before it is sent, but CSP's deprecated `report-uri` delivery requires `redirect mode "error"` on a request it leaves at `no-cors`. Chromium sends the report anyway and refuses a redirect response, which is the CSP intent; tinybrowser does the same (`RequestPolicy::CspReportUri`). Spec disagreement, recorded rather than worked around by changing the request.
- HTML's secure-context environment rule asks only for the top-level creation URL, so by its text an `http:` iframe inside an `https:` page would be secure. Chromium instead requires the frame's own URL to be potentially trustworthy and every ancestor to be secure, which is what WPT `secure-contexts/` enforces and what tinybrowser implements (`crates/secure-context`, `crates/renderer/src/js/world.rs`). Spec disagreement, recorded rather than followed off a cliff.
