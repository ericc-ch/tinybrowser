# Upstream bugs

Policy: upstream bugs stay upstream. Our code stays simple; these fail closed as known-fails. On fork syncs, upstream wins conflicts: take upstream's shape and re-apply the fork patch on top of it, even where the fork had fixed the code the change rewrites — the fork carries fixes upstream has not taken yet, not a competing design.

## Fork changes

### blitz (third_party/blitz, master)

- 87a336178 paint border edges in edge order, grouping only by colour. The per-edge fill grouped identical colours by sorting on the RGBA components, so paint order depended on the colour values: a green top border and a black left border painted black first, and along the mitre they share the later fill wins the anti-aliased pixel. The reference of `css/css-borders/border-radius-greater-than-width.html` (two neighbouring boxes, black painted last) disagreed by 100 pixels on that diagonal. Colours are now grouped in first-appearance order: the first edge of a colour fixes where the combined path is filled and later edges of that colour join it, so same-coloured sides still share one fill and different colours keep edge order. Matches Blink, which paints sides in order and draws a uniform border as one path. Upstream-able to Blitz.
- ff37545a5 split a rounded corner when an adjacent border width is zero. `CssBox::start_angle` divided by the border width of the side the arc sweeps from, so a 10px corner between a 100px border and a zero-width one computed `0 / 0` and wrote `NaN` points into `border_edge_shape`; filling that path aborted inside tiny-skia's alpha runs (`css/css-borders/border-radius-greater-than-width.html`). The closed form is now evaluated through the limits instead of dividing: an absent `bt` side puts the split at the end of its half of the quarter arc, an absent `br` side at the start, and a corner with no border on either side halves it. The ratio is rearranged to `radii.y * br_width / (bt_width * radii.x)` so it is formed once; identical for the nonzero case. Upstream-able to Blitz.
- 68cb96c13 saturate used lengths at the `LayoutUnit` limit. Stylo computes used lengths in `f32`, so a large enough `zoom`/`em` overflows the box model before layout sees it: `css/css-viewport/zoom/massive-zoom-viewbox-crash.html`'s huge zoom gives a fieldset a 2.47e26 px padding, Taffy's `available_width - insets` becomes `NaN`, and Parley's line breaker asserts on the non-finite advance and aborts. Blink is safe because every used length passes through `LayoutUnit`, which saturates at 2^25 px. `stylo_taffy::convert::saturating_px` applies that limit where stylo values become Taffy values (`length_percentage`, fit-content, border, resolved `calc()`, the padding percentage path) and where Blitz hands lengths to Parley directly (font size, line height, spacing, baseline shift, text indent). The same commit floors the inline content width at zero (a border-box narrower than its own padding, as Blink's `ComputeContentBoxLogicalWidth` does) and clamps a content slot's line advance into `0..=width`, because Parley asserts `line_max_advance <= layout_max_advance` and a negative slot is legal when padding exceeds the containing block. Upstream-able to Blitz; the saturation is a browser invariant, not a test-specific guard.
- 7eaf40f66 refuse an `@import` whose URL does not resolve. `request_stylesheet` unwrapped `CssUrl::url()`, so an empty `url()` aborted the process (`empty-background-image.html`) and, once resolved against the base URL, would have fetched the document itself. A URL-less import now joins the refused imports (too deep, unsupported condition): no sheet, no request (`https://drafts.csswg.org/css-values-4/#url-empty`). Upstream-able to Blitz.
- 87d86ebd4 ignore a stylesheet response whose owner node is gone. A document rebuilt in place (the `parsererror` tree for a non-well-formed XML response, `document.open`) drops nodes while their fetches are in flight; `load_resource` indexed the response's node unconditionally and aborted. Node ids are generation-checked, so a missing node can only be the request's own owner: installing nothing is what CSSOM says once the owner is out of the document (`https://drafts.csswg.org/cssom/#concept-css-style-sheet`), and a reused slot can never answer for it. The processing-instruction staleness check beside it already had that shape. Upstream-able to Blitz.
- 06bfef615 keep table structure out of `special_data`. The table context is a layout product, but `construct_layout_tree` stored it in the element's `SpecialElementData`, the slot that holds represented content, so anything styled `display: table` lost its content: `canvas-fallback.html`'s `#canvas4` reached the replaced-element intrinsic-size switch with `TableRoot` data and hit `unreachable!()`, aborting the run (an `<img>` would have lost its image the same way). The context now lives on `ElementData::table_root` beside `layout_data`, `IS_TABLE_ROOT` still marks the box, and the intrinsic-size match answers the remaining non-replaced variants explicitly instead of `_ => unreachable!()`. `1ae401bf0` clears the field next to `take_inline_layout`, where construction flags reset, so a box that stops being a table cannot keep a stale context that paint would read. Upstream-able to Blitz.
- 0bf7acefd do not make a boxless container an inline root. A deferred inline layout belongs to a container box, but the document node has no element data to store one on and is laid out as a block without ever reading it (`layout::compute_layout` matches `NodeData::Document` before the inline-root check). An XHTML document whose only in-flow child is the doctype (no style, so it classifies as inline) and whose root element is out of flow therefore classified the document node as "all inline", queued a dead inline layout, and `resolve_deferred_tasks` unwrapped the missing element data and aborted the process. 52 reported WPT files now run instead of panicking (`abspos-containing-block-initial-004a.xht`, `root-box-003.xht`, `position-absolute-root-element-grid.html`, ...). The embedded inline boxes are still collected, so layout children are unchanged. The wider bug is that a doctype votes as an inline child; skipping boxless node kinds in `classify_flow_children` would change the branch every HTML document takes, so it is left alone. Upstream-able to Blitz.
- 005352ba5 reject an SVG whose `clip-path` or `mask` reference chain returns to itself. usvg 0.48 converts a referenced `<clipPath>`/`<mask>` by walking its subtree and caching only the conversions that finish, so a cycle recurses until the stack overflows (`css-masking/clip-path-svg-content/clip-path-recursion-001.svg` aborted the in-process runner instead of rendering). CSS Masking has no rendering for a clip path it cannot resolve, and an empty clipping path completely clips away the element that named it (`https://drafts.csswg.org/css-masking-1/#ClipPathElement`), so the image is rejected at parse time and the `<svg>` element paints nothing. The check is an iterative DFS over the XML tree `from_data` already parses, so the guard cannot overflow its own stack. Upstream-able to Blitz; usvg should drop the offending reference itself.
- e09d70830 form submission has one plan and one keyword parser. The engine already owned the form owner, entry list, and method/action/enctype resolution, but only the entry list was reachable, and the keyword parsers an embedder had to duplicate disagreed with it: `RequestContentType` matched case-sensitively, and `form*` overrides were honored only on `<button type="submit">`, so a default-typed `<button>` and `<input type=submit|image>` lost them. `FormMethod`/`RequestContentType` are public, ASCII-case-insensitive, untrimmed parsers with `as_str`; `plan_form_submission` returns the resolved action/method/enctype/target; `reset_form_owner` removes a stale owner; `form_entry_list` emits image-button `x`/`y` and fieldset-disabled filtering; `is_submit_button` matches `type` case-insensitively. The renderer keeps its entry-list walk because it reads JS `File` objects and renderer-side value state, and its form-owner walk because `controls_to_form` is only refreshed at insertion, so an attribute write or reparent leaves it stale. Upstream-able, not a tinybrowser workaround.
- 8d970f1c3 `BaseDocument::needs_resolve` records whether style or layout is stale. Every invalidation path used to do no more than ask the shell for a redraw, so an embedder could not skip a resolve when nothing changed and had to settle after every task or every frame. The flag is set by DOM mutations, stylesheet installation, style-property writes, device changes, inline-context invalidation, focus/hover/scroll state, resource delivery, and again at the end of a pass while an animation is active; `resolve` clears it when the pass consumes the change. `request_redraw` pairs the shell request with it so a document-side invalidation site cannot keep one and forget the other; a response provider that only holds the shell handle marks the document when the message is delivered. tinybrowser's batch now settles at the rendering opportunity instead of per task. This is a behavior fix, not a compile or size trick, and should be proposed upstream once the shape has settled.
- f5e8b2551 `set_processing_instruction_attributes` is `#[must_use]`. It returns the data it stored so the caller keys its exact-unit bookkeeping off the same string the tree holds; the only caller dropped the return value and serialized the map a second time, which is the drift the return value exists to prevent.
- f770529d3 parse the `referrerpolicy` state, and restart only when it changes. The image restart check compared the raw attribute string, so `no-referrer` -> `NO-REFERRER` restarted the request and fired a second `load`, and the keyword rule lived in the embedder after the decision. `blitz_traits::net::ReferrerPolicy` is the attribute's state (eight keywords, ASCII case-insensitive and untrimmed, `None` for the missing and invalid defaults), carried on `Request` and stored in `ImageRequestState`. A restart that changes the state starts a new fetch with it; one that keeps the state joins the request the node already waits on. (`https://html.spec.whatwg.org/multipage/urls-and-fetching.html#referrer-policy-attribute`, `https://html.spec.whatwg.org/multipage/images.html#reacting-to-dom-mutations`.)
- 904be0ad0 child-list restyle handles a shadow root parent. Upstream's narrowed restyle invalidation reads the parent's selector flags on every child-list change, and a shadow root (like a fragment) has none, so the read panicked. No selector can make a shadow root a subject, so its flags are empty and the dirty marking that makes the traversal descend stays.
- 8b3564672 merge upstream main (d0f48bd17). The fork was 38 commits behind: the Stylo cd230184a upgrade, the Dioxus 0.8 sync, redraw requests through the event loop, `NetHandler::error` (failed stylesheets no longer block rendering), `display: contents` no longer a UA rule for `<picture>`, `<details>` `:open`, `background-clip: text`. Upstream still has none of the fork's deltas, so the merge keeps both sides; the one adaptation is the shadow-root selector flags above.
- 65e8b03f2 select an image source from a `srcset` attribute. An `<img>` with only `srcset` never fetched anything: any non-empty `srcset` was treated as an unselectable source set, so the element reported a broken request and fired `error` even when the attribute named a usable image. `crates::srcset` now implements "parse a srcset attribute" (descriptor tokenizer, trailing commas, error rules) and "select an image source from a source set" (drop repeated densities; smallest density at or above the device pixel ratio, else the largest, as Chromium does). Width descriptors are a parse error under the spec's own branch for a user agent without `sizes` support, so `src` remains the 1x fallback. `srcset`/`sizes` writes are relevant mutations and restart only when the selected source changes. Still open: `sizes` parsing (width descriptors, `auto`) and `<picture>` `<source>` selection. `https://html.spec.whatwg.org/multipage/images.html#parsing-a-srcset-attribute`, `https://html.spec.whatwg.org/multipage/images.html#creating-a-source-set-from-attributes`, `https://html.spec.whatwg.org/multipage/images.html#selecting-an-image-source`, `https://html.spec.whatwg.org/multipage/images.html#reacting-to-dom-mutations`.
- fea537f27 carry response taint into the image request record. An image request's outcome was reported as a bare `Started`/`Loaded`/`Failed` and the cache kept only pixels, so the response's taint and final URL were dropped at the `NetHandler` boundary and an embedder had to re-derive them from the request URL. `NetHandler::response` carries `ResponseInfo { origin_clean }`, `ResourceLoadResponse` carries it to `apply_loaded_image`, and the cache stores `CachedImage { image, origin_clean, final_url }`. `ImageRequestState` is now the element's one record (`status`, `final_url`, `origin_clean`), `ImageSettlement` drops the key, and a same-key restart joins the in-flight waiter so one request settles a node once. This is the delivery-metadata half of the fork policy for `https://html.spec.whatwg.org/multipage/images.html#updating-the-image-data` and `https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-currentsrc`; it follows 68aee6569/fdb0bdeb4 and should travel with them upstream.
- fdb0bdeb4 type an image request key by URL, and key only real requests. `ImageKey::url` was a `String` only because a source that could not be resolved was stored there as its raw text, so a resolved request and a broken one shared a stringly slot and an embedder had to `Url::parse` the key to use the URL, while the same request kept a second `Url` copy beside it. The key is now `ImageKey { url: Url, crossorigin }`, and `ImageRequestState::key` / `ImageSettlement::key` are `Option<ImageKey>`: a source that names no absolute URL starts no request, so `None` says the element is already broken, and the cache and pending maps key on the `Url` itself. Deduplication by `(url, crossorigin)` and the `Started` / `Loaded` / `Failed` sequence are unchanged. This follows 68aee6569 and should travel with it upstream.
- 68aee6569 image requests own their identity, and each node reports one settlement. Image request identity was split between Blitz and the embedder: Blitz keyed its image cache and pending map by URL, so two `<img>` on one URL with different `crossorigin` shared one request, a cache hit settled nothing, and the embedder recomputed the key by re-parsing the attribute and re-resolving the URL. `ImageKey` (URL plus parsed `CorsSetting`) is now the key, `Request` carries the initiating `node`, the parsed CORS state, and the sampled `referrerpolicy` (parsed since f770529d3), `BaseDocument::image_requests` compares request state so a same-state write does nothing, and `DocumentConfig::image_settle` reports `Started`/`Loaded`/`Failed` per node (`https://html.spec.whatwg.org/multipage/images.html#reacting-to-dom-mutations`, `https://html.spec.whatwg.org/multipage/links.html#link-type-stylesheet`). Upstream Blitz has the same URL-keyed cache and no settle event; this is a generic fix, not tinybrowser glue, and should be proposed upstream once the shape has settled (no upstream PR is open yet). `srcset` and `<picture>` `<source>` selection is still unimplemented: a broken request is reported for those elements so they do not wait for pixels that never arrive.
- f7519a948 keep one checkedness slot, reload the sheet a changed instruction names, and parse pseudo-attributes strictly. `FormControlState` has private fields and one `Dirtiness::apply`; creation, reset, and clone share one seed and one `:checked` derivation, a type change re-derives `:checked`, and `SpecialElementData::CheckboxInput` no longer carries a second checkedness copy that box construction overwrote from the `checked` attribute. A user interaction sets the dirty checkedness flag, so a later attribute write cannot undo it. A connected `xml-stylesheet` instruction reloads its sheet on a data or attribute write (`https://www.w3.org/TR/xml-stylesheet/`), the loader parses the data itself, as `CheckStyleSheet` does, so an attribute map holding a DOM-only name cannot make a parse error load, and a response for the sheet the instruction named before cannot install over the new one. Character references accept any number of leading zeros and only the lowercase `x` form.
- 9470daff5 keep a checkedness slot in every input state and gate `:checked` by the widget state. The slot was seeded and reset only for checkbox and radio inputs, so a text input's `.checked` changed after an attribute write or a reset. `store_checkedness` also mirrored `:checked` unconditionally, and the type keyword was matched case-sensitively. Typed writers take a `Dirtiness` (keep/set/clear) instead of a bool whose meaning differed per setter; the select reset clears the option dirtiness through the same write. The pseudo-attribute parser no longer rejects a character reference with long leading zeros, no longer accepts the uppercase `&#X` form XML does not define, and no longer re-validates a name it has already scanned.
- 428bd1bc1 resolve `xml5ever` to the sibling html5ever fork in `Cargo.lock`. A `[patch.crates-io]` entry does not replace a locked registry version on its own, so the workspace kept building `blitz-dom` against crates.io `xml5ever`, which has no `names` module.
- 5dfb348b5 carry a processing instruction's attribute map on its node. The strict parser is the only source for the attributes, so deriving them from the data on every read lost names the DOM attribute API accepts but the XML `Name` production rejects (an attribute local name such as `$`). Creation and every data write derive the list; an attribute mutation serializes the list into the data and stores it in one step, and the accessors read that list.
- 5ab7b943c form-control slots are the current state and the flags are the spec's dirty flags. `FormControlState` used to mean "the slot is live, otherwise read the attribute", so every writer dirtied the slot and the `Option()` constructor, the selectedness setting algorithm, and form reset could not write a slot without hiding a later attribute change; an embedder had to rebuild selectedness, dirtiness, and a pristine-value marker beside it. Now the slots are authoritative and the flags only record the spec's dirtying steps. Elements seed the slots from their initial attributes because parsers create elements with the attribute list instead of calling `set_attribute`.
- b50a4b405 parse `xml-stylesheet` pseudo-attributes with the XML grammar. The style-sheet loader scanned the data leniently while embedders parsed it strictly, so `<?xml-stylesheet href="a&b.css"?>` fetched a sheet the DOM exposed no attributes for. One strict parser answers both and a parse error loads nothing (`https://www.w3.org/TR/xml-stylesheet/#dt-parsing`). blitz-dom depends on the html5ever fork's `xml5ever::names`, which its workspace patches to the sibling submodule.
- cefc1bb08 fetch the images CSS references and send their sheet's referrer. `content: url()` and the legacy `background` content attribute make the browser load an image even when nothing paints it (`https://drafts.csswg.org/css-content/#content-property`, `https://html.spec.whatwg.org/multipage/rendering.html#the-background-attribute`). A sheet's image URLs are recorded against its location when it loads, so the request sends the sheet's URL as its referrer and applies the sheet response's `Referrer-Policy` (`https://w3c.github.io/webappsec-referrer-policy/#integration-with-css`); the document base URL moves onto the node tree so the `background` hint can resolve it. A `<style>` outside the document no longer attaches a sheet, which also removed a second parse of the same element that raced two `@import` fetches.
- e92ec16af respond to an image request under the URL it was made with, not the response URL. `pending_images` is keyed by the request URL, so a redirected delivery never matched and the image stayed pending forever. Stylesheets keep the resolved URL, which is the response URL their origin-clean check needs.
- da340bdd0 load style sheets from `xml-stylesheet` processing instructions. A `<?xml-stylesheet?>` instruction names a sheet exactly as `<link rel=stylesheet>` does, and an HTML tree keeps the instruction for compatibility with XML-authored sheets (`https://www.w3.org/TR/xml-stylesheet/`), so it has to load. The instruction owns its sheet without element storage, so the owner map records it and the unload path updates the stylist directly.
- 46d832aab give a style sheet's requests the sheet's referrer and policy. A resource a sheet references sends the sheet's URL as its referrer and applies the sheet response's `Referrer-Policy`, not the document's (`https://w3c.github.io/webappsec-referrer-policy/#integration-with-css`). `Request` carries the sheet URL, and the loaders thread each sheet's location through parsing, `@import` nesting, and `@font-face` fetches.

The BMP decode feature is not a fork change: which formats an engine carries is the embedder's compile-time choice, enabled through `crates/renderer`'s `image` dependency and unified here (commit 095af30a2 reverts the fork's own toggle).

### html5ever (third_party/html5ever, master)

- 6b8ca39 numeric character references follow the XML `Char` production. `finish_numeric` reused HTML's table, which rewrites C1 controls through windows-1252 and rejects #xD, #x7F, and the FDD0-FDEF noncharacters. XML's production (`https://www.w3.org/TR/xml/#charsets`) allows #x9, #xA, #xD, #x20-#xD7FF, #xE000-#xFFFD, and #x10000-#x10FFFF, so `&#xD;` is well-formed and a C1 reference names itself. Every tokenizer error becomes a `parsererror` document for a navigated XML response, so `css/CSS2/text/white-space-processing-00{5,6,7}.xht` rendered the error instead of the test. The supplementary-plane range is covered too: `n & 0xFFFE == 0xFFFE` rejected legal code points above the BMP, and only #xFFFE/#xFFFF of the BMP are outside the production. Upstream-able to html5ever.
- 9043b4f test every boundary of the `names` ranges and document all five productions. The earlier tests sampled a few points of the tables they sit next to, so a typo in an unsampled range stayed green.
- e2f6bcd one public `names` module for the XML `Name`, `Char`, and `S` productions. xml5ever's entity expander and tinybrowser carried byte-identical range tables, and tinybrowser carried a third copy for `createProcessingInstruction` and the pseudo-attribute parser. The module is self-contained, but upstream's tokenizer still matches `S` with literal `'\t' | '\n' | ' '` sets, so it would land without a consumer; it stays fork-only until upstream grows one, and the tokenizer keeps upstream's literals rather than rewriting twelve match arms into guards for no behavior change.
- 1753ef5 keep xmlns attributes, CDATA nodes, strict EOF/doctype. DOM trees need what out-of-band-namespace embedders do not; restores the essence of upstream #586 (reverted upstream in #595). - b71b746 skip the internal DTD subset instead of going bogus. The subset carries no tree data (expansion runs up front) but its presence must not poison the doctype token.
- 39ba978 / bac928b prolog-only documents, then EOF-before-root is an error. First half accepted rootless input, then the start-phase half was reverted: the XML document production requires exactly one root, as Gecko and Chromium enforce. Unclosed roots are still caught in the end phase.

### rquickjs (third_party/rquickjs, master)

- Nested realms under a live `Ctx`. `Context::full` and `Context::with` took
  the runtime's `RefCell`/`Mutex` unconditionally, so an embedder that already
  held the lock (the normal case inside `outer.with(...)`) could not create or
  enter a second realm: the single-threaded path aborted on a double borrow
  and the parallel path deadlocked. `Runtime` now carries the raw
  `JSRuntime` pointer, and the single-threaded path tries the lock first and
  falls back to `JS_NewContext`/`Ctx::new` through the raw pointer when the
  current thread already owns it. QuickJS allows creating a context while
  another is running, and the live guard keeps the runtime exclusive; the
  parallel runtime keeps blocking on the lock because it has no reentrant
  owner. A unit test creates, enters, and drops a nested realm under a live
  one and reuses the outer realm afterwards. This lets the renderer run an
  inline script inserted into another document's live realm synchronously
  instead of deferring every cross-realm insertion to the next drain.

Exotic hooks for WebIDL legacy platform objects (dcd8edd, 9bcc543, 42688aa, 31e1683, 62d9c1a, 09be401, f99e205, 52744cf, cfc6c77, de4b9d9). The shared QuickJS class installed get/has/set callbacks for every exotic object, hiding prototypes and swallowing ordinary assignment. Now each Rust type registers only its derived hooks with explicit fallthrough to the ordinary path, so OwnPropertyKeys ordering, IsDataDescriptor, and receiver/holder distinction match WebIDL. Each engine-side fix has a binding proof that was red before it.

- d73fbda safe realm-aware native callbacks with copyable dispatch state. Callbacks keep argument counts, receive new.target, and run in their creation realm; Copy/Send/Sync-only state fits GC (no Rust destructors mid-collection).
- 8842327 UTF-16 string conversion preserving lone surrogates. WebIDL DOMString conversion keeps every code unit; pairs with the blitz UTF-8 open issue below (JS side preserves, DOM side does not).
- 103de1e survive caught panics and regenerated binding types. A panic caught across FFI poisoned the mutex and broke every later call; plus an MSVC atom-type build fix and per-target test gating.
  - tinybrowser's release profile cannot honor this: `panic = "abort"` means std's `catch_unwind` never catches, so a Rust panic in a native callback aborts the renderer instead of raising a JS exception. Catching requires unwinding, measured at 13.59 MiB vs 10.61 MiB shipped (+2.98 MiB, `docs/size.md`), so it stays rejected; the panic hook records the panic with location (`crates/logging/src/crash.rs`) and callback paths must stay panic-free. The guard remains correct for unwind hosts (tests, embedders).
