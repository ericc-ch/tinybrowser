# 07: Navigation-facing API

Type: grilling

Question: What does the navigation lifecycle need from `net` beyond the
core type model?

Answer:

- **Nothing new — navigation is an ordinary request**: `agent.request(
  Method::Get, url, Context::Navigation).send()`. Status-as-data means
  error-status pages render like any page; cookies ride inside `send()`
  (ticket 05); `final_url()` names the document after redirects; the Body
  feeds the parse pipeline. Non-GET navigations (form submissions) work
  because Method is caller-chosen.
- **Redirect-chain exposure: deferred to CDP.** Nothing consumes the hop
  list today; the Network domain will define the shape devtools need.
  `final_url()` covers all current consumers.
- **Referrer stays a plain header** (`Referer`) set by `browser` — no
  dedicated `net` knob in v1. Canonical referrer policy computation
  (`strict-origin-when-cross-origin` etc.) belongs to the stealth
  milestone.
- **Error pages are generated by `browser`**, not `net`: transport-level
  failures surface as `NetError` and the embedder renders its own page.
